## High‑Level Architecture

```
concert-tickets-management/
├─ contracts/                # Solidity contracts (business logic on‑chain)
│   └─ *.sol                # Smart contract source files
│   └─ abi.json             # ABI generated from the compiled contracts
├─ public/                  # Static assets served by Next.js (images, favicons)
├─ src/
│   ├─ pages/               # Next.js page components
│   │   ├─ _app.jsx         # Global CSS import and root App component
│   │   └─ index.jsx        # Main UI page – mirrors the original static HTML
│   ├─ scripts/             # Front‑end JavaScript that drives the DApp
│   │   └─ script.js         # Uses ethers.js to interact with the contract
│   └─ styles/               # Global stylesheet (style.css)
├─ package.json             # NPM scripts and dependencies (next, react, ethers)
└─ README.md                # Project description (currently empty)
```

### UI Layer (Next.js)
- **`src/pages/_app.jsx`** imports a global stylesheet (`src/styles/style.css`) and renders the page component.
- **`src/pages/index.jsx`** implements the main UI. It keeps the original HTML structure and IDs from the prototype `index.html` so that the existing `script.js` can manipulate the DOM unchanged.
- The page loads `src/scripts/script.js` lazily via a dynamic `import` in a `useEffect` hook, then manually dispatches a `DOMContentLoaded` event to trigger the script’s initialization.

### DApp Logic (`src/scripts/script.js`)
- Uses **ethers.js** to connect to MetaMask (`window.ethereum`).
- Loads the contract ABI from `./abi.json` and creates a `ethers.Contract` instance bound to the user’s signer.
- Provides a set of **read‑only** wrappers (e.g., `readOwner`, `readTicketPrice`) and **transaction** helpers (e.g., `purchaseOfficial`, `transferTicket`).
- UI updates are performed by directly mutating DOM elements identified by the IDs present in `index.jsx` (e.g., `#walletDisplay`, `#officialState`).
- Admin actions (sale configuration, ticket management) are gated behind the admin dashboard UI and use a generic `sendAdminTx` helper.

### Smart‑Contract Layer
- The on‑chain contract lives in `contracts/`. The front‑end only needs the compiled **ABI** (`abi.json`) and the contract address defined in `script.js` (`CONTRACT_ADDRESS`).
- All state changes (sale opening, ticket purchase, transfer, check‑in, RTB) are initiated from the UI and reflected back through read‑only calls.

## Project‑Specific Tips for Claude Code
- **Running the app**: After `npm install`, use `npm run dev` to launch the Next.js dev server (default `http://localhost:3000`). The UI will automatically import `script.js` and connect to MetaMask.
- **Contract interaction**: Ensure MetaMask is set to the network matching `EXPECTED_CHAIN_ID` (default mainnet – `0x1`). Update `CONTRACT_ADDRESS` in `script.js` if you deploy to a testnet.
- **Adding tests**: No test framework is currently configured. Consider adding Jest or Playwright for component and integration tests, then expose a `test` script in `package.json`.
- **Linting/Formatting**: The repo does not include ESLint/Prettier configs yet. Adding them will enable `npm run lint` and consistent code style.
- **Static assets**: Images referenced in the UI live under `public/assets/...`. When adding new assets, place them in `public/assets` and reference them with a leading `/` (e.g., `/assets/images/new.png`).
